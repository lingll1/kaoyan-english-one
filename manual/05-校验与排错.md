# 05 · 校验与排错

## 1. 六个脚本各查什么

| 脚本 | 查什么 | 通过时输出 | 失败时 |
|---|---|---|---|
| `build.py` | 数据格式 + 构建 | `词数 387 / 校验 通过` | 打 `!` 告警，**仍会生成产物** |
| `verify.py` | 正文 token 拼回去是否与 `SOURCE.md` 逐字一致 | `全部一致。` | 指出「第几段第几个 token」 |
| `qc.py` | 题目区三文件是否互相对齐 | `全部对应正确。` | 列出缺块或词序列差异 |
| `_final.py` | 成品结构计数 + 硬编码扫描 | `全部检查通过。` | 列出问题行 |
| `_allcheck.py` | 按数据文件逐个核对产物体例 | `全部 N 篇结构核验通过。` | `!! 缺 xxx.html` |
| `_rootindex.py` | 生成跨年份入口页 | `→ docs\index.html（N 个年份，已生成 M 篇）` | — |

**注意 `build.py` 的告警不会中止构建**。它照样写出 HTML，只是顺手打一行 `!`。所以「文件生成了」不等于「数据对了」——必须回头看告警。

## 2. `build.py` 的告警逐条读

### `! 缺少 text1.lesson.json`
`data/` 里没有对应的结构与内容文件。`build.py` 会退化成「只输出正文」模式，题目区、段意、语法点全没有。补齐文件即可。

### `! 缺少 text1.quiz.txt（题干与选项的逐词标注 + 中文整句译文）`
少了题目区逐词数据。产物里题干与选项会退回**无标注的纯文本**——能看，但不符合本项目的格式要求。

### `! 音标格式可疑：operators|ˈɒpəreɪtəz|n. 运营商`
音标没有用 `/.../` 包裹。检查那一行是不是漏了斜杠，或者用了方括号 `[...]`。

### `! 释义过长（13 字）：subsidise|...|v. 补贴（给某人提供财政支持使其降低价格）`
去掉词性前缀与括号后仍超过 11 个汉字。**这是排版红线**：注释越宽，词位越宽，一行能放下的词越少，最后整页稀稀拉拉。改短，或者把解释移到「语法点」里。

### `! 缺释义：the|/ðə/|`
竖线后面是空的。标点行才允许写 `|_|_`，实词必须给释义。

### `! para_notes 段号 ...` / `! 第 3 段缺少语法点`
`words.txt` 的段数与 `lesson.json` 的 `para_notes` 对不上，或者某段 `grammar` 是空数组。两边必须一一对应。

### `! 真题数量 4` / `! 变体数量 3`
阅读题要求真题 5 道、变体 6 道。翻译题真题也是 5 道。数量不对就补。

### `! 题 21 缺少逐词块 @stem:21`
`lesson.json` 里第 21 题存在，但 `quiz.txt` 里没有对应块。常见原因：
- 块标记拼错（`@stem: 21` 多了空格、`@STEM:21` 大小写）
- 选项字母不连续（有 A、B、D 缺 C）
- 变体编号与渲染时强制重编号后的 `V1..V6` 对不上

### `! 题 21 的 @stem:21 缺少中文整句译文（~ 开头一行）`
那个块末尾没有 `~` 行。注意 `~` 必须是**块内最后一行的第一个字符**。

### `! JSON 错误：Expecting ',' delimiter: line 42 column 8`
`lesson.json` 语法坏了。行号是 JSON 解析器的行号，直接定位过去看。最常见的是中文引号 `""` 当成英文引号用、或者尾随逗号。

## 3. `verify.py` 的报错怎么读

### `! 第 2 段第 47 个 token 不一致：你的「rises」vs 原文「rise」`
最有用的一类报错。它会同时打印你的词与原文的字符，通常还带上下文窗口。

排查顺序：

1. **先确认哪边对**。多数是 `words.txt` 抄错，但也可能是 `SOURCE.md` 本身错了（见 [04-操作流程.md](04-操作流程.md) 第四步那个 `saying` / `maxim` 的例子）。
2. 如果差的是**标点**：检查是不是漏写了一个 `|_|_` 行，或者把 `,` 写成了全角 `，`。
3. 如果差的是**空格**：`verify.py` 比对时会去掉所有空白，所以空格差异不会报错。报错说明是实打实的字符不同。
4. 如果差的是**大小写**：比对时统一转小写了，所以大小写也不会报错。
5. 如果差的是**弯引号/直引号**：比对时统一了弯引号（`""` ↔ `""`），所以不报。

### `! 段号不一致：你的 4，原文 6`
`words.txt` 的 `@N` 数量与 `SOURCE.md` 的 `### 第 M 段` 数量不同。要么漏抄了一段，要么 SOURCE 里把一段拆成了两段。

## 4. `qc.py` 的三条线

`qc.py` 独立于 `build.py`，自己读三个文件互相比对，查三件事：

1. **块是否齐**：算 `sum(1 + len(options))` 得到应有块数（阅读是 11 题 × 5 = 55），与 `quiz.txt` 里实际块数比。
2. **块名是否对**：`quiz.txt` 里的 `@stem:` / `@opt:` 标记，能否与 `lesson.json` 的题目编号一一映射。
3. **词序列是否一致**：把 `quiz.txt` 每块的词按顺序拼起来，与 `lesson.json` 对应 `stem` / `options` 的文本去空白后比对。

第 3 条最常抓出问题——典型场景是只改了 `lesson.json` 里的题干措辞，忘了同步改 `quiz.txt`，于是词序对不上。

## 5. `_final.py` 与 `_allcheck.py`

`_final.py` 做两件事：

- **结构计数**：每篇应有 55 个 `para qz`、55 个 `qzcn`、11 个 `article.q`，以及 4 个块类 `blk k1`–`k4`。
- **硬编码扫描**：抓 `释义只有省略号、没有实义`（比如 `keep|v. 使……不` 这种被截断的释义）。

> 注意 `_final.py` **故意不把 `……` 和 `...` 判为错误**。这两个符号在本项目里是合法用法：`...` 出现在语法点结构模板里（`It is all very well ..., but ...`），`……` 出现在词典式释义（`prep. 在……中`）和语法点（`把……当作……`）里。只有「整条释义只有省略号、没有任何实义」才算错。

`_allcheck.py` 按 `data/*.lesson.json` 逐个核对产物，**不要求固定篇数**——数据有几份就核验几份。所以它既能用于完整项目（7 年 49 篇），也能用于只有一篇的样例仓库。

它抓得最准的是**块类名拼错**：`blocks[].k` 写成「难题解析」而不是「难点解析」，那个块就掉样式，肉眼很难发现，但 `_allcheck.py` 会因为它数不到 `blk k4` 而报错。

## 6. 不报错但难看的问题

这几类脚本查不出来，得靠眼睛。

### 某一行词距特别大
正常现象。词位宽度 = max(词宽, 音标宽, 释义宽)，旁边站着一个释义较长的词就会有空白。如果实在难看，把那个词的释义改短。

### 行首出现孤立标点
理论上不会——`render_para` 已经把后置标点并进前一个词、前置标点并进后一个词。如果还是出现了，检查是不是写成了独立的破折号 token：破折号是**故意**保留独立站位的（`side=None`），它会自己占一个词位。

### 直引号贴错了边
`"` 分不出开闭，`build.py` 用**奇偶配对**处理：第 1、3、5…个贴后一个词，第 2、4、6…个贴前一个词。如果某段引号没配对（比如引用了半句就结束），后面的引号会全部错位。解决办法：**用弯引号 `""`** 代替直引号 `"`，`punct_side` 对弯引号能直接判开闭，不依赖配对。

### 打印时注释糊成一团
内置 `@media print` 会把 `--an` 缩到 9px。如果还要更清楚，在浏览器打印设置里调大缩放比例，或者用「中」圆钮先切到大字号再打印。

### 朗读没声音
见 [01-环境说明.md](01-环境说明.md) 第 3 节。最可能的原因是**没有本地英文语音、当前又断网了**。其次检查浏览器标签页是否被静音（地址栏右侧会有个划掉的喇叭图标）。

## 7. 环境类问题

### `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`
Windows 控制台默认 GBK，打不出 `✓`。八个脚本开头都已经插了 `sys.stdout.reconfigure(encoding="utf-8")` 保护，正常情况下不会出现。如果你自己新写了脚本要打印 `✓`，记得加同样三行。

另一个绕过办法：运行时加 `-X utf8`，或者在 PowerShell 里先设 `$env:PYTHONIOENCODING='utf-8'`。

### `ModuleNotFoundError: No module named 'docx'`
只有 `_docx2source.py` 需要它：`pip install python-docx`。

### 中文文件名在某些环境下出问题
产物文件名是中文（`英语一2021_阅读Text1.html`）。Windows 与 macOS 没问题；Linux 上如果 locale 不是 UTF-8，可能显示成乱码但文件本身正常。脚本内部一律用 `pathlib` 处理路径，不做字符串拼接，所以功能不受影响。

## 8. 一条命令查全套

```bash
python build.py && python qc.py && python _final.py && python _allcheck.py && python _rootindex.py
```

`verify.py` 没放进这条链里，是因为它按篇校验、需要逐篇调；全量跑请用循环：

```bash
for n in 1 2 3 4; do python verify.py 2021 $n; done
```
