# 04 · 操作流程

从「手上只有一份真题」到「一篇可以看的文档」，是这六步。每一步后面都有一个验收门，过不了就别往下走——数据错了，后面全是白做。

```
① 拿到整卷  →  ② 转 SOURCE.md  →  ③ 填答案  →  ④ 校对 SOURCE.md
                                                        ↓
   ⑥ 构建 + 六道校验  ←  ⑤ 生产三份数据（words / quiz / lesson）
```

## 第一步：拿到整卷

**优先找 Word 版整卷**，其次才是网页文本。

原因很直接：网页版真题几乎都是扫描识别（OCR）来的，标点和空格经常粘连。我踩过最狠的一个例子，某站 2023 全卷的正文是：

```
Caravanseraiswereroadsideinnsthatwerebuilt...
```

整句没有空格。另一处 Text 4 的 36–40 题题干也是整段连写。这种文本没法用，得逐字重打。

而整卷 docx 是排过版的，段落结构完整、标点正确。判断标准很简单：**用 `python-docx` 读出来，段落数是否合理、句子是否带空格**。

> 本仓库不提供真题下载，也不附获取链接。请自备合法来源的真题材料。

一份整卷 docx 的典型结构（`python-docx` 读出 281 个非空段落时）：

| 内容 | 大致段落位置 |
|---|---|
| 完形填空正文 5 段 | `ps[4..8]` |
| 完形 20 题选项 | `ps[9..108]`，每行形如 `[ A ] Still` |
| `Text 1` 标题 | `ps[113]` |
| `Text 2` / `Text 3` / `Text 4` | `ps[145]` / `ps[178]` / `ps[210]` |
| `Part B` | `ps[242]`（注意 `Section III Writing` 下还有第二个 `Part B`，要取**首次**出现） |
| `Part C` | `ps[254]` |
| `Section III Writing` | `ps[262]` |

段落号每年都不同，但**章节标题的文本是稳定的**（`Text 1`、`Part B`、`Part C`、`Section III`），所以脚本按文本定位，不按固定下标。

## 第二步：转成 SOURCE.md 骨架

```bash
pip install python-docx          # 只在用这个脚本时需要
python _docx2source.py 2025
```

它会读 `2025/2025_full.docx`，生成两个文件：

- `2025/SOURCE.md` —— 阅读四篇：`## Text N` + `### 第 M 段` + `### 题目`，题干与 A–D 选项都在，答案先写成 `**答案 ?**` 占位
- `2025/SOURCE-others.md` —— 完形填空（空格写作 `__N__`）+ 20 题选项、新题型 Part B（候选段落 + 已知顺序链）、翻译 Part C（原文含 `(46)`–`(50)` 标记，划线句单列，参考译文写 `**参考译文 ?**`）

已知的坑：

- `Part B` 在整卷里出现两次（阅读的 Part B 和作文的 Part B），脚本取首次出现。
- Text 4 有时在 docx 里被拆成很多段（混进了选项与子项），提取结果段数会明显多于正文真实段数，需要人工合并。

## 第三步：填答案与参考译文

把核定好的答案写进 `2025/_ans.json`：

```json
{
  "reading": "CDABB DABCA AACBD DCBDC",
  "cloze":   "ADBCB CADAD DDCAB CCBBA",
  "partb":   { "41": "B", "42": "E", "43": "A", "44": "G", "45": "D" },
  "trans":   { "46": "…", "47": "…", "48": "…", "49": "…", "50": "…" }
}
```

```bash
python _fillans.py 2025
```

它会按出现顺序把 `**答案 ?**` 和 `**参考译文 ?**` 全部替换掉，末尾自动检查两个文件的占位符计数是否为 0。

`reading` 与 `cloze` 是**连写的字母串**，中间可以有空格，脚本会去掉。`trans` 可以省略，省略时脚本会尝试从 `2025/_web/SOURCE-others.web.md` 里提取（前提是你之前存过网页版）。

**答案必须自己核对过再用**。网上的答案经常互相矛盾，实测过 2026 Text 4 第 36 题，不同站点给出 `B` 和 `D` 两个答案——最后是回原文找到 `bore more than 20 fire scars` 这句才定案。脚本只负责填，不负责判断对错。

## 第四步：校对 SOURCE.md

这一步不能省。生成的骨架一定有问题，常见的是：

- docx 里的软连字符、全角标点、多余空格
- 段落被错误合并或拆开
- 题干里的下划线占位被吞掉
- `Part B` 的候选段落顺序与原文不一致

校对方法：拿一两个独立来源交叉比对，或者直接与整卷 docx 的原文对照。**发现分歧时，以 docx 原文为准**——不是因为 docx 更权威，而是因为网页版十有八九是 OCR 的，而 docx 至少是排过版的。

> 一个真实的例子：2021 Text 3 的 `SOURCE.md` 原本写 `ran one popular Victorian saying` 和 `blackened teeth`，用整卷 docx 逐段比对后发现原文是 `maxim` 和 `gnashers`。`gnashers` 是英式俚语「牙齿」，与全文调侃口吻一致，所以按 docx 改了 `SOURCE.md` 和配套的 `words.txt`。

这一步之后，`SOURCE.md` 就是**唯一权威底本**，后面所有数据都必须向它看齐。

## 第五步：生产三份数据

这是工作量最大的部分，三份文件互不依赖，可以并行做（这个项目当初就是拆成三份并行）：

| 文件 | 内容 | 参考规格 |
|---|---|---|
| `data/textN.words.txt` | 正文逐词：`词\|音标\|本句词义` | [02-数据格式.md](02-数据格式.md) 第一节 |
| `data/textN.quiz.txt` | 题干与选项逐词，块标记 `@stem:` / `@opt:` | 同上第二节 |
| `data/textN.lesson.json` | 段意、语法点、题目、解析、变体、词汇、主旨 | 同上第三节 |

写的过程中可以随时单点验证，不用等全部写完：

```bash
python verify.py 2025 1     # words.txt 写完就能验
python qc.py     2025 1     # quiz + lesson 都写完才能验
```

### 生产时的硬性要求

这些不是建议，是脚本会卡的红线：

- **音标一律 `/.../` 包裹**，带 `ˈ` `ˌ`，英式口音。
- **释义去掉词性前缀与括号后不超过 11 个汉字**。超了排版会崩（词位太宽，一行放不下几个词）。
- **标点单独成 token**，写 `|_|_`。
- **所有格合并进单词**：`operators'|/ˈɒpəreɪtəz/|n. 运营商（所有格）`。
- **`the` 后接元音写 `/ði/`**，否则 `/ðə/`。
- **每题 4 块，`k` 值顺序固定**：原句含义 → 语法辨析 → 难点解析 → 易错点解析。
- **每块 quiz 末行有 `~` 中文译文**。
- **变体固定 6 道，答案别全写成同一个字母**。

### 关于变体

六道变体的题型要与真题错开，覆盖不同的解题能力。常用组合：

| 变体类型 | 考什么 |
|---|---|
| 词义句意题 | 根据上下文猜一个短语的意思 |
| 指代题 | `it` / `that` / `they` 指什么 |
| 态度题 | 作者对某事的倾向 |
| 例证作用题 | 某段某例是为了说明什么 |
| 否定事实题 | 原文**没有**提到哪一项 |
| 段落作用题 | 某段在全文中的功能 |
| 推理判断题 | 从原文能推出什么 |
| 细节因果题 | 某事发生的原因 |

答案分布要打散。清一色 A 的变体对自测毫无价值——这一点是实测发现的：某一年的六个变体原本答案全是 A，后来逐个打散成 C/B/D/B/C/D，同步改了易错点解析里各选项的字母。

## 第六步：构建与校验

```bash
python build.py 2025 1       # 构建单篇
python verify.py 2025 1      # ① 正文与 SOURCE.md 逐字一致
python qc.py     2025 1      # ② 题目区三文件互相对齐
python _final.py 2025        # ③ 成品结构计数 + 硬编码扫描
python _allcheck.py 2025     # ④ 按数据文件逐个核对产物

python build.py              # ⑤ 全部年份全量重建
python _rootindex.py         # ⑥ 生成跨年份总入口页
```

六条都过，一篇就算完成。有任何一条报错，看 [05-校验与排错.md](05-校验与排错.md)。

## 顺序上的两个提醒

1. **`build.py` 会重建 `docs/index.html`**，但**单篇模式（`build.py 2025 1`）不会**。所以加完一篇新文档后，要么跑一次 `python build.py 2025`（整年重建），要么跑 `python _rootindex.py`，否则入口页里看不到它。
2. **`_rootindex.py` 用的词数是 `words.txt` 里实际统计的非标点 token 数**，不是 `lesson.json` 的 `meta.words`。后者是估值，两者经常对不上（样例里 `meta.words` 写 400，实际 387）。入口页以实际为准。
