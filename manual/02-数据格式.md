# 02 · 数据格式

一篇文档由三份数据文件喂给 `build.py`，另外有一份 `SOURCE.md` 作为唯一文本来源。四个文件的分工：

```
SOURCE.md            ← 唯一文本来源。正文、题干、选项、答案都在这里，人工核对过
  │
  ├─ data/textN.words.txt    ← 正文逐词：词 | 音标 | 本句词义
  ├─ data/textN.quiz.txt     ← 题干与选项逐词：块标记 + 词行 + 中文译文
  └─ data/textN.lesson.json  ← 段意、语法点、题目、解析、变体、词汇表、主旨
                                   ↓
                             build.py
                                   ↓
        docs/英语一YYYY_阅读TextN.html
```

后三份**都必须与 `SOURCE.md` 逐字对齐**。这是整个项目的硬约束，`verify.py` 和 `qc.py` 就是拿来卡这条线的。

---

## 一、`words.txt` —— 正文逐词标注

行式纯文本，UTF-8 编码，一行一个 token。

```
# Text 1 · 英国铁路票价再涨 逐词标注
# 格式：词|音标|本句词义（段前 @段号；标点行音标与释义写 _）

@1
How|/haʊ/|adv. 怎么
can|/kæn/|modal. 能
the|/ðə/|art. 定冠词
train|/treɪn/|n. 火车
operators|/ˈɒpəreɪtəz/|n. 运营商
possibly|/ˈpɒsəbli/|adv. 究竟（加强语气）
justify|/ˈdʒʌstɪfaɪ/|v. 为…辩解
yet|/jet/|adv. 又（再一次）
...
@2
has|/hæz/|v. 已经
...
```

### 语法

| 写法 | 含义 |
|---|---|
| `#` 开头 | 注释行，构建时忽略 |
| `@1` `@2` … | 段号，其后所有 token 属于该段 |
| `词\|音标\|本句词义` | 一个词条，用竖线分三段 |
| `,\|_\|_` | **标点也占一个 token**，音标与释义都写 `_` |

### 为什么标点要单独占 token

因为 `verify.py` 的工作方式是：把 `words.txt` 的全部 token 按顺序拼成一句话，去掉空格、统一弯引号与破折号、转小写，再和 `SOURCE.md` 里对应段落比对。**只有 token 序列完整包含标点，拼回去才和原文一字不差**，才能抓出漏词、多词、拼写走样。

而渲染时，`build.py` 会把这些标点并进相邻的词（后置标点贴前一个词、前置标点贴后一个词、破折号单独站），所以读者看到的还是正常的 `operators,`、`(CPI)`，不会出现行首孤零零一个逗号。

### 词条规则

- **音标一律 `/.../` 包裹**，带重音符号 `ˈ` `ˌ`，用英式（`en-GB`）。`check()` 会校验这一点。
- **释义格式**：`词性 + 空格 + 本句词义`，如 `n. 运营商`。词性用 `n. v. adj. adv. prep. conj. pron. modal. art. num. det.`。
- **释义写「本句中的意思」**，不是词典第一个义项。同一个词在不同篇里可以给不同释义。
- **释义长度**：去掉词性前缀与括号内容后，**汉字不超过 11 个**，超了 `build.py` 会打 `!` 警告。这条限制是为了排版——注释太长会把词位撑宽，一行放不下几个词。
- **所有格合并进单词**：写 `year's|/jɪəz/|n. 年（所有格）`，不要拆成 `year` + `'s`。
- **`the` 的口音**：后接元音音素时写 `/ði/`，否则 `/ðə/`。
- **多词合并**：`according to`、`web-based` 这类按原文的分词方式处理；原文是连字符的词保持连写。

## 二、`quiz.txt` —— 题干与选项逐词标注

格式与 `words.txt` 几乎一样，多了一层「块」的概念。

```
# Text 1 题目区逐词标注（2021 英语一 · 第 21–25 题 + 6 道变体）
# 块标记 @stem:<题号> / @opt:<题号>:<A|B|C|D>；词行 词|音标|本句含义；~ 开头为中文整句译文。

@stem:21
The|/ðə/|art. 定冠词
author|/ˈɔːθə/|n. 作者
holds|/həʊldz/|v. 认为
that|/ðæt/|conj. 引导宾语从句
this|/ðɪs/|adj. 今年的
year's|/jɪəz/|n. 年（所有格）
increase|/ˈɪŋkriːs/|n. 上涨
...
~ 作者认为今年铁路客运票价的上涨 ______。

@opt:21:A
will|/wɪl/|modal. 将
ease|/iːz/|v. 减轻
train|/treɪn/|n. 火车
operators'|/ˈɒpəreɪtəz/|n. 运营商（所有格）
burden|/ˈbɜːdn/|n. 负担
~ 会减轻火车运营商的负担

@opt:21:B
...
```

### 块标记

| 标记 | 对应 |
|---|---|
| `@stem:21` | 第 21 题题干 |
| `@opt:21:A` | 第 21 题 A 选项 |
| `@stem:V1` | 第 1 道**变体**的题干 |
| `@opt:V3:D` | 第 3 道变体的 D 选项 |

变体一律按 `V1`…`V6` 编号，**与 `lesson.json` 里变体自己的 `no` 字段无关**——`build.py` 渲染时会强制重编号为 `V1..V6`，这样不同年份数据里变体编号写成 `1..6` 还是 `V1..V6` 都能正常工作。

### `~` 行

每块**末行**以 `~` 开头，写这一块的中文整句译文：

```
~ 作者认为今年铁路客运票价的上涨 ______。
```

渲染出来是英文下方那条浅蓝色的「译」行。`qc.py` 会检查每一块**都有** `~` 行，缺一个就报错。

### 题量

- 阅读 Text 1–4：每题 5 块（题干 + 4 选项），5 题真题 + 6 题变体 = **55 块**
- 完形填空：20 空 × 5 块 = **100 块**
- 新题型 Part B：5 题 × (1 + 选项数) 块，七选五/八选五常见是 40 块
- 翻译 Part C：5 句 × 5 块 = **25 块**（翻译题的选项块仍需存在，选项内容可写「无」的占位——见 `SPEC-OTHER.md`）

## 三、`lesson.json` —— 结构化内容

UTF-8 JSON，六个顶层键。

```json
{
  "meta": {
    "paper": "英语一",
    "year": 2021,
    "part": "A",
    "no": 1,
    "qs": "21–25",
    "theme": "英国铁路票价再涨：涨价理由、罢工补偿与国有化威胁",
    "words": 400,
    "difficulty": "中等偏难",
    "tags": ["经济民生", "议论文", "作者态度题"],
    "file": "英语一2021_阅读Text1.html",
    "source": "2021 全国硕士研究生招生考试 英语（一）阅读理解 Part A Text 1"
  },
  "para_notes": [ ... ],
  "questions": [ ... ],
  "variants": [ ... ],
  "glossary": [ ... ],
  "summary": { ... }
}
```

### `meta`

| 字段 | 作用 |
|---|---|
| `part` | **决定题型分派**：`"A"` 阅读 / `"cloze"` 完形 / `"B"` 新题型 / `"C"` 翻译。缺省按 `"A"` |
| `no` | 阅读是 1–4；其他题型随意（只用于排序） |
| `qs` | 题号区间，显示在页头 |
| `theme` | 主题一行，显示在页头，并进总入口页 |
| `words` | 词数（**估值**，仅作参考；总入口页用的是实际统计） |
| `difficulty` / `tags` | 页头标签 |
| `file` | **已不再使用**。文件名由 `build.py` 按 `part` + `no` 统一生成，改这个字段不会生效 |

### `para_notes` —— 每段一条

```json
{
  "n": 1,
  "trans": "然而，按照这种说法，凭什么要让林肯郡一位开车的退休老人，去补贴萨里郡一位股票经纪人的日常通勤？",
  "grammar": [
    {
      "h": "① 反问问句 Why ... should ... ?",
      "b": "结构：Why, the argument goes, should a car-driving pensioner ... have to subsidise ...?  \n考点：the argument goes 是插入语，把反问句从中间切开。\n例：Why should taxpayers fund a service they never use?"
    }
  ]
}
```

- `n` 必须与 `words.txt` 里的 `@n` 一一对应，**段数对不上 `check()` 会报错**。
- `trans` 是这段的中文译文，渲染成「段意」卡片。
- `grammar` 每条 2–3 个，`b` 里用**三个固定行首**：

  ```
  结构：…（这句话的骨架，标出主干与修饰）
  考点：…（这条语法点为什么在这里重要、判断方法是什么）
  例：…（一个同结构的中文对照例句）
  ```

  渲染时每行会拆成独立段落，所以不要把三行挤在一段里。也可以加第四行「搭配：」「注意：」「提示：」，同样自行成段。

### `questions` —— 真题

```json
{
  "no": 21,
  "type": "细节题",
  "stem": "The author holds that this year's increase in rail passenger fares ______.",
  "options": {
    "A": "will ease train operators' burden",
    "B": "has kept pace with inflation",
    "C": "is a big surprise to commuters",
    "D": "remains an unreasonable measure"
  },
  "answer": "D",
  "locate": "第一段第③句（配合第②句）",
  "blocks": [
    { "k": "原句含义", "t": "定位句：**This year's rise, an average of 2.7 per cent, may be a fraction lower than last year's, but it is still well above the official Consumer Price Index (CPI) measure of inflation.**\n译为：今年的涨幅平均为 2.7%，或许比去年略低一点点，但仍远高于官方消费者物价指数（CPI）所衡量的通胀水平。" },
    { "k": "语法辨析", "t": "① 让步转折框架 may be ... but it is still ...：may be 表让步..." },
    { "k": "难点解析", "t": "真正的难点是态度判断而非事实提取..." },
    { "k": "易错点解析", "t": "- **A. will ease train operators' burden（将减轻运营商负担）**：无中生有..." }
  ]
}
```

- `stem` 与 `options` 里的文本**必须与 `quiz.txt` 对应块的词序列完全一致**（标点、连字符、弯引号都要一样），这是 `qc.py` 卡的第二道线。
- `answer` 是单个大写字母。
- `locate` 显示成「答案 D　定位：…」。
- `blocks` **必须恰好四条，且 `k` 的顺序固定**：

  ```
  原句含义 → 语法辨析 → 难点解析 → 易错点解析
  ```

  渲染时它们分别套用 `k1`–`k4` 四个 CSS 类（米黄 / 淡蓝 / 淡紫 / 淡粉）。拼错一个字（比如写成「难题解析」）那个块就会掉样式，`_allcheck.py` 会把它抓出来。

- `t` 支持极简 Markdown：`**粗体**`、`*斜体*`、反引号、`- ` 开头的列表、`\n` 换行。

### `variants` —— 变体题

字段与 `questions` 相同，多一个 `tag`（如 `"变体 1 · 词义猜解"`），少一些约束：

- **固定 6 道**。少于 6 道 `check()` 报错。
- 题型要与真题错开，常见组合：词义句意、指代、态度、例证作用、否定事实、段落作用、推理判断、细节因果。
- 六个答案**不要全是同一个字母**——这是给人自测用的，全 A 等于没有自测价值。

### `glossary` / `summary`

```json
"glossary": [
  { "w": "subsidise", "ipa": "/ˈsʌbsɪdaɪz/", "pos": "v.", "cn": "补贴", "note": "sub-（下）+ sid（坐），本义「坐底下垫着」" }
],
"summary": {
  "main_idea": "本文围绕英国铁路客运票价再度上涨展开……",
  "structure": [
    { "h": "第一段 现象与质疑", "b": "票价平均涨 2.7%，高于通胀，作者以反问开篇" }
  ]
}
```

`glossary` 渲染成「核心词汇」表，`summary` 渲染成「全文主旨」卡片 + 结构分解。

## 四、`SOURCE.md` —— 唯一文本来源

Markdown，按篇分节：

```markdown
## Text 1

### 第 1 段

How can the train operators possibly justify yet another increase to rail passenger fares? ...

### 第 2 段

...

### 题目

21. The author holds that this year's increase in rail passenger fares ______.

A. will ease train operators' burden
B. has kept pace with inflation
C. is a big surprise to commuters
D. remains an unreasonable measure

**答案 D**
```

`verify.py` 只读 `## Text N` 下的 `### 第 M 段`，把 `words.txt` 的 token 拼回去逐段比对。`SOURCE.md` 是人工核对过的权威文本，其余文件向它看齐；发现不一致时，**先确认哪边对，再改错的那边**——多数情况是 `SOURCE.md` 对，但样例里的 2021 Text 3 恰恰是反过来改了 `SOURCE.md`（`saying` → `maxim`、`teeth` → `gnashers`），因为整卷 docx 才是权威底本。

## 五、跑一遍看看

改完任何一份数据，跑这三条：

```bash
python build.py 2021 1     # 有 ! 告警就说明数据格式有问题
python verify.py 2021 1    # 正文是否与 SOURCE.md 逐字一致
python qc.py 2021 1        # 题目区三个文件是否互相对齐
```

三条都过，再跑 `python _final.py 2021` 和 `python _allcheck.py 2021`，确认成品结构完整。
